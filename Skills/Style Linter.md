# Style linter

`tools/style_lint.py` checks the rules in [[Coding Principles]] that a machine can check.
It uses only the Python standard library, so it runs anywhere Python 3.10 or newer is installed.

```bash
python3 ~/Downloads/agent-vault/tools/style_lint.py src  # on William's Mac
```

In a cloud session, where the vault is checked out next to the repo, run `python3 ../agent-vault/tools/style_lint.py src`.

It prints `path:line: rule message` for each finding and exits with status 1 if there are any.

## Rules

| Rule | What it flags | Fix |
| --- | --- | --- |
| `nested-ternary` | A conditional expression inside another, or two on one line | Use `if` and `else` statements |
| `nested-comprehension` | A Python comprehension with more than one loop | Use a `for` loop |
| `lambda-in-comprehension` | A lambda inside a Python comprehension | Use a named function |
| `long-boolean` | More than 4 conditions in one Python expression | Name the parts, like `is_ready` |
| `long-chain` | More than 3 chained calls in one expression or line | Store steps in named variables |
| `swallowed-error` | Bare `except`, empty handler, empty `catch {}`, or an ignored Luau `pcall` | Handle, log, or rethrow |
| `line-too-long` | Code lines over 120 characters. Comment-only lines are skipped. | Split the line |

Python is checked with the `ast` module, so those findings are exact.
TypeScript, JavaScript, C#, and Luau are checked line by line after strings and comments are blanked.
Those checks can miss cases or, rarely, flag a line that is fine.

## Silencing a finding

Add a comment containing `style-lint: ignore` on the flagged line and say why:

```python
value = a if b else c if d else e  # style-lint: ignore generated by the schema tool
```

Silencing should be rare. If a rule is wrong for a whole repo, change the constant at the top of the script instead.

## Using it in another repo

Formatters and linters the repo already has (StyLua, Selene, ESLint, Ruff) come first.
Run this linter as well, since those tools do not check for nested ternaries or swallowed errors in the same way.
To enforce it in CI, copy `tools/style_lint.py` into the repo and run it as a step.
